# 통합 기록 허브 설계

## 목적과 목표

기록 화면에서 콘텐츠 종류가 뒤섞이고 로또 기록이 별도 화면에 갈라지는 문제를 줄인다. 한 화면에서 날짜순 기록을 보고 `전체·타로·손금·로또·체크·명언`으로 빠르게 거를 수 있게 한다.

## 범위

- `/history`를 단일 기록 허브로 정리한다. 최근 체크 점수 차트처럼 기록 유형 하나에만 적용되는 시각 요소는 메인 목록에서 덜어낸다.
- 브라우저 로컬 저장소의 기존 기록과 `/api/lotto/history`의 서버 기록을 읽어 표시 항목 형태로 정규화한다. 같은 로또 추첨이 로컬과 서버 양쪽에 있으면 `result_id` 기준으로 한 번만 표시한다.
- 필터는 `전체·타로·손금·로또·체크·명언`을 제공한다. 체크 안의 재물 흐름/소비 스타일 등은 `체크`로 묶는다.
- 로컬 기록은 기존 브라우저 저장소, 로또 기록은 기존 API를 사용한다. 저장 방식, 사용자 식별, 로그인은 변경하지 않는다.
- 로또 기록을 불러오지 못해도 로컬 목록은 보여주고, 실패 상태를 구분해 안내한다.
- `/lotto/history`는 기존 주소로 들어오는 이용자를 위해 유지하며, 통합 기록의 로또 필터가 열린 상태로 연결한다.
- 목록이 길어지면 자연스러운 세로 스크롤을 허용한다.

## 제외 범위 및 접근 방식

기록 이관/삭제, 로그인 계정 연동, 기기 간 동기화, 로컬 저장소 30개 제한 변경은 포함하지 않는다. 서버 데이터 스키마는 그대로 두고 화면에서만 두 기록 원천을 결합한다. 저장 출처가 다르다는 점은 짧고 분명한 개인정보/저장 안내로 계속 알린다.

## 구현자의 판단

날짜는 한국 현지 시각으로 정렬한다. 체크 관련 type(`future`, `money`, `spending`)은 같은 필터에 포함한다. 기록이 비어 있거나 특정 필터에 결과가 없을 때 각각 알맞은 빈 상태를 보여준다.
