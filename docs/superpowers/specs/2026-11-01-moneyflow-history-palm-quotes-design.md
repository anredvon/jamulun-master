# 머니플로우 기록·손금·투자 한 줄 설계

## 의도

메인 화면을 사용자가 고른 네 가지 가벼운 활동 중심으로 정리하고, 활동별 결과를 기록 화면에서 다시 볼 수 있게 한다. 손금 기능은 사용자의 최초 손바닥 사진에서 확인한 선 유형을 결과 조합에 반영한다. 사진은 기기 밖으로 보내지 않고 보관하지 않는다. 투자 콘텐츠는 출처가 확인되는 짧은 한 줄 명언으로 제공한다.

## 현재 상태와 근거

- 코드 후보 저장소는 `anredvon/jamulun-master`의 `main`, 검토한 기준 커밋은 `5d1e854c1aa7de971049e562ee10551c391741a2`다.
- 현재 작업 공간에는 앱 소스 체크아웃이 없고 문서만 있다. 구현은 설계 승인 후 분리된 Git 체크아웃에서 시작한다.
- 현재 `templates/result.html`은 퀴즈 결과를 `moneyflow_history_v1`에 기록한다. `static/js/history.js`는 같은 키를 읽고 30개까지 렌더링한다.
- `static/js/tarot.js`는 `moneyflow_tarot_collection_v2`에 카드 발견 정보를 저장하지만, 완성된 타로 리딩을 머니 기록에 저장하지 않는다. 실사이트에서 결과를 만든 뒤 기록 목록이 비어 있던 현상과 맞는다.
- 현재 이력은 점수 있는 퀴즈 결과 형태에 맞춰져 있다. 손금과 명언 기록은 점수가 없으므로 공통 이력 항목은 점수를 선택값으로 다뤄야 한다.
- 저장된 GitHub 설명에 따르면 PR #1은 병합됐지만 AWS 배포 전제는 준비 상태였고, 현재 공개 IP 사이트가 어떤 소스 리비전으로 실행 중인지는 확인하지 못했다. 코드 수정은 가능하나, 공개 배포 전 실제 실행 리비전과 배포 경로를 다시 확인한다.

참고 코드: [result.html](https://github.com/anredvon/jamulun-master/blob/5d1e854c1aa7de971049e562ee10551c391741a2/templates/result.html), [history.js](https://github.com/anredvon/jamulun-master/blob/5d1e854c1aa7de971049e562ee10551c391741a2/static/js/history.js), [tarot.js](https://github.com/anredvon/jamulun-master/blob/5d1e854c1aa7de971049e562ee10551c391741a2/static/js/tarot.js).

## 목표

- 메인 화면에 네 가지 진입점을 둔다: 오늘의 타로카드, 사진 기반 오늘의 손금, 짧은 재물 흐름 체크, 오늘의 한 줄 투자 명언.
- 하단 메뉴는 `홈 / 오늘 / 체크 / 기록`으로 정리한다. `오늘`은 타로·손금·명언 허브이며, `체크`는 간단한 재물 흐름 체크로 연결한다.
- 서로 다른 활동의 결과를 하나의 기기 내 기록 목록에서 날짜순으로 다시 볼 수 있게 한다.
- 사진 손금은 사용자의 사진에서 잡은 후보 선 유형을 확인하고 수정한 뒤 결과를 정한다.
- 투자 명언은 인용문과 화자·출처를 함께 보여주고, 원문 출처 링크를 제공한다.

## 제외 범위와 방지할 동작

- 손 사진을 외부 AI, 별도 에이전트, 원격 API로 보내지 않는다.
- 원본 손 사진을 서버·데이터베이스·기기 기록에 저장하지 않는다. 기록에는 선 유형과 결과 텍스트만 남긴다.
- 손금 결과를 건강 진단, 수익 보장, 구체적인 투자 매수·매도 권유처럼 표현하지 않는다.
- 모든 기록을 다른 기기와 동기화하거나 계정 로그인 기능을 추가하지 않는다. 기존 안내와 같이 브라우저 기기별 저장으로 유지한다.
- 기존 결과·공유·DB 기록을 삭제하거나 변경하는 마이그레이션을 하지 않는다.
- 대문 경로 `/`는 기존 인트로 화면을 유지하고, `/home`은 네 기능을 고르는 앱 홈으로 유지한다.

## 구현 접근과 선택

### 1. 기록 저장

- **기기 내 공통 기록 목록 (선택):** 현재 `localStorage` 기반 기록을 확장한다. 기존 퀴즈 기록은 호환하고, 타로·손금·명언 완료 시 공통 저장 함수를 호출한다. 앱에 로그인과 서버 동기화가 없고 기록 안내도 기기 저장을 약속하므로 가장 작은 변경으로 기대를 맞춘다.
- **서버 저장:** DB에 새 기록 모델과 소유권·보존 정책을 추가해야 한다. 기기 사이 동기화가 목표가 아니므로 이번 요청 범위를 넘는다.

공통 항목은 안정적인 식별자, 종류, 제목, 날짜, 표시용 요약, 선택 점수, 종류별 메타데이터를 포함한다. 기존 퀴즈 점수는 유지한다. 기록 목록은 네 종류를 모두 표시하고, 그래프는 비교 가능한 재물 체크 점수만 사용한다. 점수가 없는 항목에 0점이나 가짜 점수를 보여주지 않는다. 기존 30개 보관 한도를 유지한다. 저장 오류나 손상된 데이터가 있어도 결과 화면 자체는 계속 보인다.

### 2. 손금 조합

- **선 유형 조합형 (선택):** 마음선 5종 × 두뇌선 5종 × 운명선 4종으로 100가지 조합을 만든다. 코드에서는 각 유형의 표시 순서가 바뀌어도 ID가 유지되도록 안정된 유형 ID로 조합을 계산한다. 각 조합에는 유형명, 짧은 해석, 오늘의 한마디가 있다.
- **결과 문구 100개를 각각 단독 작성:** 결과별 어조는 다양하게 만들기 쉽지만, 손 그림의 선과 결과가 일치하도록 관리하기 어렵고 콘텐츠 수정 비용이 커진다.

선택한 흐름은 촬영 안내 → 사진 선택/촬영 → 기기 내 선 후보 표시 → 마음선·두뇌선·운명선 유형 확인·수정 → 선을 훑는 애니메이션 → 조합 결과 → 결과 기록 저장이다. 후보를 잡기 어려운 사진은 재촬영을 권한다. 사진 속 선 후보는 제안값이며, 사용자가 확인·수정한 유형만 조합 결정에 쓴다. 권한을 거부하거나 사진을 선택하지 않은 경우 사진 없이 무작위 조합으로 대체하지 않고 안내 화면에 머문다.

브라우저 안의 전통적인 이미지 처리로 선 후보를 제안한다. 촬영 조명·피부 결·손 위치가 달라 자동 판독 품질이 일정하지 않을 수 있으므로, 정확도를 약속하지 않는다. 후보를 확인하거나 수정하는 화면을 필수로 둔다. 사진은 처리에만 쓰고 저장·전송하지 않는다. 이 방식이 실제 기기 사진에서 충분히 작동하는지 구현 중 소규모 검증이 필요하다. 판독 품질이 기준을 못 맞추면 사진 분석을 실제 기능처럼 출시하지 않고 범위와 접근법을 다시 협의한다.

목업에서 확인한 화면 표현은 `사진 안내 → 예시 손금선 확인 및 유형 수정 → 조합 결과`다. 예시 그림은 실제 자동 인식의 증거가 아니며, 결과 조합은 사용자가 확인한 세 가지 유형에서 계산된다.

### 3. 오늘의 한 줄 투자 명언

기기 안의 편집된 명언 목록에서 한 줄을 뽑는다. 각 항목은 짧은 인용문, 화자, 출처 제목과 링크를 가진다. 정확한 출처를 확인할 수 없는 유명인 문구는 싣지 않는다. 개인별 매매 권유로 오해되지 않도록 투자 권고가 아닌 읽을거리라고 안내한다. 결과를 뽑으면 같은 공통 이력 목록에 기록한다.

### 4. 메뉴와 기존 기능

- 홈은 네 가지 기능 카드를 제공한다.
- `오늘`은 타로·손금·명언을 모은 허브다. 타로 직접 경로는 계속 유지한다.
- `체크`는 짧은 재물 흐름 체크로 연결한다. 기존 소비 스타일·오늘의 재물운 경로는 이전 결과·링크 호환을 위해 삭제하지 않고, 메인 카드에서는 우선순위를 낮춘다.
- `기록`은 활동 종류와 날짜를 구분해 보여준다. 타로 카드 컬렉션은 별도 수집 기능으로 유지하고 개별 리딩을 머니 기록에도 추가한다.

체크 화면은 기존 `/intro/future`의 5문항·약 30초 흐름을 재사용하고, 홈과 하단 메뉴에서 `재물 흐름 체크`로 안내한다. 새 문항 풀이나 새 채점 체계는 만들지 않는다. 이는 현재 기능을 합쳐 간결하게 보이게 하려는 사용자 요청에 맞춘 구현 판단이다.

## 제약과 사전 조건

- 현재 앱은 Flask 템플릿과 정적 JavaScript를 사용한다. `requirements.txt`와 `.env.example`에는 이미지 인식 또는 AI 서비스가 설정돼 있지 않다.
- 손 사진 입력은 모바일 Safari와 Android Chrome을 우선 지원한다. 사용자가 직접 시작하는 카메라 촬영과 사진 보관함 선택을 모두 제공하고, 카메라 호출이 지원되지 않으면 보관함 선택으로 진행한다. 데스크톱은 사진 파일 선택을 지원하되 카메라 기능은 보장하지 않는다. 실제 특정 휴대폰 모델은 사용자의 별도 지정이 없는 한 구현 기본값으로 삼지 않는다.
- 구현은 현재 공개된 저장소 `main` 커밋을 후보로 삼되, 배포된 공개 IP 인스턴스의 소스 리비전과 작업 트리를 공개 배포 전에 확인한다.
- 현재 작업 폴더는 Git 저장소가 아니므로 앱 변경은 별도 격리 체크아웃에서 진행한다. 기존 작업 공간 문서와 다른 수정은 보존한다.
- 이 설계 승인만으로 원격 브랜치 푸시, PR 병합, AWS 설정·스냅샷·서비스 변경 또는 공개 배포를 승인한 것으로 보지 않는다. 해당 단계는 배포 소스와 기존 운영 조건 확인 후 별도로 다룬다.

## 구현자가 결정할 부분

- 기기 내 선 후보 추출의 구체적인 임계값과 촬영 품질 안내 기준. 후보가 불안정하면 정직하게 재촬영 또는 사용자의 유형 수정을 안내한다.
- 100개 손금 조합의 실제 한국어 결과 문구와 유형 이름. 전통 손금 해석에서 착안한 재미용 언어로 작성하고 건강·수익 단정은 피한다.
- 출처 확인된 투자 명언의 초기 수량과 표기 형식. 짧은 문구만 싣고, 각 항목에 원문 출처를 남긴다.
- 손금 결과·명언을 기록에 추가하는 정확한 완료 시점, 중복 방지 ID, 점수 없는 항목의 목록 UI.

## 승인 후 작업 순서

1. 독립 checkout/worktree를 만들고 기준 커밋·작업 트리 상태를 확인한다.
2. 공통 기록 형식과 저장 경로를 구현해 타로 리딩 누락을 바로잡고 기존 퀴즈 기록과 호환한다.
3. 기록 목록에 종류별 점수/요약 표시를 추가하고 재물 체크 점수 그래프의 범위를 제한한다.
4. 홈과 하단 메뉴를 네 기능 구조로 바꾸고 `오늘` 허브를 추가한다.
5. 온디바이스 손금 사진 흐름, 후보 유형 수정, 100개 조합, 결과 저장을 구현한다.
6. 출처가 확인된 한 줄 투자 명언 목록과 뽑기·저장 흐름을 추가한다.
7. 실제 사진 판독의 품질과 기록 표시를 검토한다. 공개 사이트 배포는 실행 소스·운영 조건·별도 승인을 확인한 뒤 진행한다.
